# Gardenia 项目评审与改进建议

> 评审对象：Gardenia（栀花的个人网站）
> 评审日期：2026-11-11
> 评审方式：通读全部源码与配置、检查 `dist/` 构建产物、执行一次 `pnpm build` 验证；初始评审未修改源码。
> 实施状态：用户在评审后确认实施。P0、性能、SEO 基础项、无障碍与工程化第一批已于 2026-11-11 落地，结果与剩余项见第十节。
> 运行环境：Windows / Node 24.21.0 / pnpm 11.5.2

---

## 一、结论摘要

这是一个**视觉完成度很高、工程底子干净**的单页个人网站：夜色 + 暖灯的氛围统一，Astro 组件划分合理，CSS 变量集中，渐进增强和无障碍的基础动作（`prefers-reduced-motion`、skip link、`focus-visible`、装饰元素 `aria-hidden`）都做到了。仓库的许可证拆分（代码 MIT / 图片保留所有权利 / 第三方图标声明）也相当专业。

主要问题集中在三处：

1. **一处功能与界面脱节（已定方案）**：移动端「陀螺仪倾斜视差」的脚本和样式都在，但没有入口。已决定不补按钮，改为 Android 自动启用、iOS 静默跳过，首屏零新增 UI（见 P0-1、5.1）。
2. **性能成本与页面体量不匹配**：为了一个鼠标光斑引入了完整的 React（约 208 KB JS / 64 KB gzip），字体每页实际拉取约 872 KB，首屏大图 337 KB，CSS gzip 48 KB。
3. **内容与元信息还是半成品**：副标题为空、便签全是占位文案；缺少 `og:image`、canonical、sitemap、robots、404 页，分享出去没有预览图。

## 二、做得好的地方

1. **设计语言集中管理**。颜色、字体、间距、阴影、缓动全部收敛在 `src/styles/tokens.css`，组件里没有散落魔法值，后续换主题成本低。
2. **Astro 用法正确**。页面壳、导航、区块、页脚各司其职；组件样式默认 scoped，只有需要穿透的地方用 `:global`；脚本按需加载，没有把整站做成 SPA。
3. **渐进增强做得细**。`has-js` 类在 `<head>` 内联添加，禁用 JS 时内容不会因 `[data-reveal] { opacity: 0 }` 而消失；`IntersectionObserver` 缺失时直接显示；`prefers-reduced-motion` 在 CSS、React、canvas、平滑滚动四处都有判断。
4. **无障碍基础到位**。`lang="zh-CN"`、skip link、`:focus-visible` 描边、装饰层 `aria-hidden`、社交图标有 `aria-label`、正文图片有描述性 `alt`。
5. **图片管线正确**。使用 `astro:assets` 的 `<Image>`，带 `widths` / `sizes`，输出 WebP 多尺寸，首屏图 `loading="eager"` + `fetchpriority="high"`，其余懒加载。
6. **仓库治理专业**。`LICENSE`（MIT）、`LICENSE-IMAGES`（图片保留所有权利）、`NOTICE` 三层拆分写得很清楚，第三方品牌图标也单独声明，这是很多个人项目缺失的。
7. **命名与注释**。BEM 风格的类名一致，中文注释解释的是「为什么这样设计」（如「向上融进夜色」），而不是复述代码。

## 三、问题清单（按优先级）

### P0：功能与内容的一致性

#### 1. 陀螺仪功能「有代码、无入口」——已实施：方案 A（首屏零新增 UI）

`src/components/sections/Hero.astro:530` 的脚本在找 `[data-motion-toggle]`：

```ts
const motionButton = document.querySelector<HTMLButtonElement>('[data-motion-toggle]');
```

但模板里（`Hero.astro:34-42`）没有这个按钮。样式 `.motion-toggle`（`Hero.astro:223-285`）、`aria-pressed` 状态、权限申请、设备方向监听都写好了，`motionButton` 却始终是 `null`，导致 `coarsePointer` 分支永不激活，手机端实际没有倾斜视差。

**决策（2026-11-11）：采用方案 A。** 不补任何可见入口，只在「不需要用户授权」的设备上自动启用；iOS 不启用、不弹窗。具体改动见 5.1。

理由与代价：

- 首屏的留白是当前最干净的部分，在标题下加胶囊控件会把视觉重心从文案拉走；
- Android Chrome 在 HTTPS 下通常可以直接监听 `deviceorientation`，可以做到用户无感；
- iOS 13+ Safari 必须在用户手势中调用 `requestPermission()`，零 UI 就拿不到权限。方案 A 明确接受这个取舍：**iOS 放弃该效果，首屏保持干净**；
- 桌面鼠标视差、canvas 火星、减少动效判断都不受影响。

曾评估但未采用的备选：

- **方案 B**：把开关移到页脚，复用 `.lights-out` 的细边框小按钮。能覆盖 iOS，但会给页脚增加一个非核心控件，且可发现性差；
- **方案 C**：在 `.hero__content` 里补胶囊按钮。功能能通，但明确否决——不应让画面迁就代码。

需要清理的死代码：`.motion-toggle` 的全部样式、`motionButton` / `setMotionLabel` / `stopMotion` / `requestMotionAccess` 这套按钮与权限逻辑。不要留下「看起来实现了、实际没接上」的中间态，它比纯净的缺失更容易误导后来维护的人。

### P1：性能（本轮已实施，数据见第十节）

#### 3. 为一个光标光斑引入完整 React

`src/pages/index.astro:17` 使用 `<CursorGlow client:load />`，构建产物：

| 文件 | 原始 | gzip |
| --- | --- | --- |
| `client.*.js`（React 运行时） | 208 KB | 64 KB |
| `react.*.js` | 8 KB | 3 KB |
| `CursorGlow.*.js` | 1 KB | 1 KB |

而组件本身只有 46 行、一个 `requestAnimationFrame` 跟随效果（`src/components/atmosphere/CursorGlow.tsx`）。同时 `client:load` 会在首屏立即水合，和 LCP 大图抢带宽。

**建议：改写成一段原生脚本，移除 `@astrojs/react`、`react`、`react-dom`、`@types/react*` 依赖。** 页面会少约 70 KB gzip 的 JS，构建也更简单。实现可直接放进 `index.astro`：

```astro
<div class="cursor-glow" aria-hidden="true"></div>

<script>
  const glow = document.querySelector<HTMLElement>('.cursor-glow');
  const fine = matchMedia('(pointer: fine)').matches;
  const reduced = matchMedia('(prefers-reduced-motion: reduce)').matches;

  if (glow && fine && !reduced) {
    let x = innerWidth / 2;
    let y = innerHeight * 0.4;
    let tx = x;
    let ty = y;
    let raf = 0;

    const tick = () => {
      x += (tx - x) * 0.12;
      y += (ty - y) * 0.12;
      glow.style.transform = `translate3d(${x}px, ${y}px, 0)`;
      raf = requestAnimationFrame(tick);
    };

    addEventListener('pointermove', (event) => {
      tx = event.clientX;
      ty = event.clientY;
      glow.classList.add('is-on');
    }, { passive: true });

    document.addEventListener('visibilitychange', () => {
      cancelAnimationFrame(raf);
      if (!document.hidden) raf = requestAnimationFrame(tick);
    });

    raf = requestAnimationFrame(tick);
  }
</script>
```

如果暂时不想动依赖，最低成本的缓解是把 `client:load` 换成 `client:idle`，并加 `client:media="(pointer: fine)"`（触屏设备直接不水合）。但这只是止血，React 依然会被下载。

#### 4. 字体是最大的单页负载：每页约 872 KB

`BaseLayout.astro:2-3` 引入了两套字体：

- `@fontsource-variable/noto-sans-sc`：构建出 **99 个 woff2、共 12 MB**，CSS 里 **102 条 `@font-face`**（部分直接 base64 内联，把 CSS 撑到 125 KB / gzip 48 KB）。
- `@fontsource/lxgw-wenkai/500.css`：**只有 latin 子集**。

按页面实际出现的字符和 `unicode-range` 静态匹配，这个单页会请求 **16 个字体文件、约 872 KB**。对一张只有三屏的个人主页来说，这个成本明显过高，而且 `font-display: swap` 会导致文字先以回退字体出现、再整体换字，产生视觉跳动。

另外有一个容易被忽略的问题：**`@fontsource/lxgw-wenkai` 的 `500.css` 只包含拉丁字母，不含汉字。** 也就是说 `--font-display` 里写的「LXGW WenKai」对中文标题并不生效，`Hero` 标题、About 标题实际使用的是系统楷体（`Kaiti SC` / `KaiTi`），在没装楷体的 Linux/Android 上会退到默认衬线体——**不同系统看到的标题字形并不一致**。同时标题 `font-weight: 400`，而字体只声明了 500，字重也对不上。

建议按以下优先级处理：

1. **正文改用系统字体栈，移除 Noto Sans SC**。`--font-body` 里已经有 `PingFang SC`、`Microsoft YaHei`，中文正文用系统字重完全够用，可立即省掉 872 KB/页和 12 MB 产物。
2. **标题字体做子集化后自托管**。用 `pyftsubset`（fonttools）或 `cn-font-split` 只保留站内实际用到的汉字（当前页面约 100 个不同码位）+ 常用标点 + latin，产出通常只有 20～40 KB，中文标题才能真正用上霞鹜文楷，且跨平台一致。
3. 如果选择保留 Noto，也应对全站字符做子集化，而不是加载 fontsource 的完整分片；并把字重区间和标题实际使用的 `font-weight` 对齐。

如果采用子集化，记得在仓库里加一个 `pnpm fonts` 脚本（或 `scripts/subset-fonts.mjs`），并在 README 写明「改文案后需重新生成字体子集」，否则以后新增文字会缺字。

#### 5. 首屏大图 337 KB

`src/assets/photos/orchard.jpg` 原图 4096×3072（362 KB），`Hero.astro:14` 输出到 1920 w 的 WebP 为 **337 KB**，是 LCP 资源。图片本身是夜景，噪点多、压缩率低。

建议：

- 输出格式改为 AVIF（同画质通常比 WebP 小 40%～50%），保留 WebP 作为 `picture` 回退；
- 桌面端最大宽度降到 1600 或 1440（当前 `sizes="100vw"`，大部分屏幕不需要 1920）；
- 质量参数从默认值下调（如 55～65），夜景照片的观感损失很小；
- 首屏图可以加 `<link rel="preload" as="image" imagesrcset="…">`，让 LCP 更早开始。

#### 6. favicon 体积异常

`public/favicon.ico` 为 **172 KB**，内部包含 16/32/48/64/128/256 六个位图，其中 256×256 一项就占 118 KB；`apple-touch-icon.png` 另占 61 KB。

建议：

- 主图标改为 `favicon.svg`（矢量，通常 1～3 KB）；
- 保留一个 32×32 PNG 作为旧浏览器回退；
- `apple-touch-icon` 压到 180×180、几 KB 即可；ICO 最多保留 16/32/48 三个尺寸；
- `<head>` 中按现代写法声明：

```html
<link rel="icon" href="/favicon.svg" type="image/svg+xml" />
<link rel="icon" href="/favicon-32.png" sizes="32x32" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
```

### P2：可访问性与交互细节

1. **skip link 只滚动、不移动焦点**。`BaseLayout.astro:35` 指向 `#about`，但 `<section id="about">` 没有 `tabindex="-1"`，键盘用户按 Tab 后焦点仍停在链接上。给目标加 `tabindex="-1"`，或改为跳到 `<main id="main">`。另外跳过的其实是首屏内容，语义上「跳到主要内容」更合理。
2. **当前栏目没有 `aria-current`**。`SiteNav.astro` 只用 `.is-active` 类表示选中，读屏软件感知不到。在 `updateActive` 里同步 `link.toggleAttribute('aria-current', ...)` 或设置 `aria-current="location"`。
3. **页脚版权文字对比度不足**。`.site-footer__copy` 使用 `rgba(201, 174, 149, 0.46)`、11px，在 `#090706` 上实测对比度约 **2.7:1**，低于 WCAG AA 的 4.5:1。建议提高到 0.65 以上，或把字号提到 12px。
4. **便签标签同样偏淡**。`.note__label` 的 `rgba(74, 52, 40, 0.55)` 在纸色背景上约 3.1:1，10px 小字，建议加深到 0.7 左右。
5. **「芜狐 ↑」按钮的语义不明确**。它实际功能是回到顶部，建议可见文案改为「回到顶部 ↑」，或至少加 `aria-label="回到顶部"`。同理，页脚「啊内个内个内个内个」如果只是彩蛋，可以保留，但不要作为唯一的信息传达。
6. **移动端便签三列过窄**。`About.astro:387-410` 在 375px 屏上每列约 106px，减去内边距只剩约 88px 文本宽度，12px 字每行 7 个字，非常挤。建议 ≤560px 改为单列或横向滑动，并适当增大字号。
7. **固定导航与锚点**。页面上有两个带 `id` 的跳转目标，建议统一加 `scroll-margin-top`（约 72px），避免未来加内容后被固定导航遮住。
8. **iOS 安全区**。页脚底部与「回到顶部」按钮靠近屏幕下缘，可加 `padding-bottom: max(42px, env(safe-area-inset-bottom))`，避免被 Home Indicator 压住。

### P2：工程与仓库

1. **没有 README**。新人（包括三个月后的自己）需要知道：用 pnpm、`dev/build/preview` 三个命令、如何部署、图片与字体怎么处理、许可证如何拆分。这是当前最值得补的一份文档。
2. **`images/` 下有 1.5 MB 原始照片被提交**（`images/梨园.jpg`、`images/栀子花_.jpg` 等 5 张），但源码只引用 `src/assets/photos/` 里的文件。这些原图既没被使用，也没在 README 说明用途，建议移到单独的归档仓库/网盘，或明确写进文档：「此处为原始素材，构建不引用」。
3. **缺少类型检查与格式统一**。`package.json` 只有 `dev/build/preview`，但装了 `typescript`。建议增加 `"check": "astro check"`（需安装 `@astrojs/check`）、`"format": "prettier --write ."`，并在 CI 中跑 `check + build`。
4. **没有 CI/部署配置**。至少加一个 GitHub Actions：安装依赖 → `pnpm check` → `pnpm build`，产物作为 artifact；部署到 Vercel/Cloudflare Pages/GitHub Pages 任选其一并在 README 说明。
5. **`package.json` 缺少 `packageManager` 与 `engines`**。仓库使用 pnpm + lockfile，但没有声明版本，容易出现「npm install 后 lockfile 被改写」的问题。建议加：

```json
"packageManager": "pnpm@11.5.2",
"engines": { "node": ">=22" }
```

6. **`docs/` 之前是空目录**，现在放下了本文档；后续可以把设计决策、字体子集流程、部署说明都放这里。
7. **死代码**：`.hero__scroll` 及其 `fall` 动画（`Hero.astro:344-377`、`430-442`）没有任何对应 DOM；`.motion-toggle` 的样式也处于「有样式无元素」状态。前者如果要加提示就补标记，如果追求首屏极简就直接删样式；后者按 P0-1 的方案整体删除或补入口。别让后来者误以为功能存在。
8. **导航逻辑分散**。`BaseLayout.astro:41-48` 监听滚动切换 `.is-scrolled`，`SiteNav.astro:101-131` 又监听一次滚动计算当前栏目。建议合并到 `SiteNav` 内，用一个 `IntersectionObserver` 或单个 `scroll` 回调处理两种状态，减少重复监听和跨组件耦合（布局层不应该知道 `[data-nav]`）。
9. **`CursorGlow` 的样式放在页面里**（`index.astro:20-44`）。组件自身不带样式，复用时必须记得复制那段 `:global`。改成 Astro 组件（或把样式放进组件旁边的 `.css`）更内聚。
10. **连续动画的耗电问题**。`CursorGlow` 的 rAF 永不停止；页面不可见时浏览器会降频，但切回后仍在为空转。建议在 `pointerleave` 或无指针移动 1～2 秒后暂停，移动时再恢复。
11. **`background-attachment: fixed` + 三个全屏混合图层**（`global.css:22`、`.grain`、`.vignette`）在移动端滚动时开销偏高。建议在 `(pointer: coarse)` 下关闭 `background-attachment: fixed`，或把颗粒层用 `@media (max-width: 900px)` 降低不透明度/直接隐藏。
12. **`will-change` 长期存在**。`Hero` 的图片、光晕、星层都常驻 `will-change: transform`，会长期占用合成层内存；只在动画激活时添加更稳妥，不过对单页影响有限，属于打磨项。

### P3：细节与一致性

1. **首屏缺少「向下滚动」提示**。样式和动画（`.hero__scroll`）已经写好，但没有标记。补上后能自然引导用户进入 About：

```astro
<a class="hero__scroll" href="#about" aria-label="向下滚动，查看关于我">
  <span>SCROLL</span><i aria-hidden="true"></i>
</a>
```

如果更看重首屏的绝对干净，这一步也完全可以不做——直接删掉 `.hero__scroll` 的样式与 `fall` 动画即可。它属于锦上添花，不是缺失；判断标准应该是它是否让画面更好，而不是「代码都写了不用可惜」。

2. **`--font-display` 的字重不匹配（已修正）**：fontsource 的 `500.css` 实际包含的是 Regular 400 字形。自托管子集已按真实字重声明 `font-weight: 400`，About 与 404 标题也统一为 400，避免浏览器合成伪粗体。
3. **星点使用了全局字符串类名**：`Hero.astro:510` 生成 `star white` / `star yellow`，是运行时拼接的全局类名，容易和其他组件的 `.star` 冲突。建议改成 `hero__star--white` 这类带前缀的 BEM 名。
4. **`about__side` 的旋转与 hover 覆盖**。`.window-card` 基础样式有 `transform: rotate(3deg)`，`.about__side` 又用 `nth-child` 覆盖，hover 再覆盖一次。规则能工作，但阅读成本高；建议只保留一处定义，用 CSS 变量控制角度。
5. **`site-footer` 的版权年份硬编码 2026**。如果站点长期维护，可以改为构建时年份或直接写「© Gardenia」。
6. **页面只有一个 `<h2>`**。About 的标题是 h2，页脚没有标题层级，问题不大；如果以后加「文章/动态」区块，注意保持 h1 → h2 → h3 的层级。
7. **`About.astro:67` 的 emoji 行**。如果作为装饰，建议加 `aria-hidden="true"`，避免读屏逐个念出「猫脸」；如果作为内容，请换成有意义的文字。

## 四、建议的修改路线

### 5.1 方案 A 实施记录（移动端晃动，已完成）

**状态：已实施（2026-11-11）。** 首屏无新增 DOM；Android 自动启用，iOS 静默跳过；桌面与减少动效行为不变。以下保留当时的实施步骤，作为改动依据。

目标：**首屏不新增任何 DOM**；Android 自动启用倾斜视差；iOS 静默跳过；桌面鼠标视差与减少动效行为不变。

#### 第 1 步：删除按钮样式

删除 `Hero.astro:222-285` 整段（从 `/* 触屏设备：用倾斜手机驱动背景视差 */` 到 `@keyframes motion-pulse` 结束），包括：

- `.motion-toggle`、`.motion-toggle:hover`、`.motion-toggle[aria-pressed='true']`
- `.motion-toggle__dot` 及其 `[aria-pressed='true']` 变体
- `@media (pointer: coarse) { .motion-toggle:not([hidden]) { ... } }`
- `@keyframes motion-pulse`

同时删掉 `@media (prefers-reduced-motion: reduce)` 动画列表里的 `.motion-toggle__dot`（`Hero.astro:479` 附近），否则会留下悬空选择器。

#### 第 2 步：删除按钮与权限逻辑

在 `Hero.astro` 的 `<script>` 中删除以下内容（保持 `handleOrientation`、`motionBaseline`、`motionTargetX/Y`、`motionActive` 不动，帧循环仍在用）：

| 位置（约） | 内容 |
| --- | --- |
| `Hero.astro:530` | `const motionButton = document.querySelector…` |
| `Hero.astro:655-658` | `setMotionLabel` |
| `Hero.astro:660-672` | `stopMotion` |
| `Hero.astro:674-690` | `requestMotionAccess` |
| `Hero.astro:692-717` | `if (motionButton && coarsePointer …) { … }` 整个按钮分支 |

#### 第 3 步：替换为自动启用

在 `handleOrientation` 定义之后、`IntersectionObserver` 之前插入：

```ts
const OrientationEvent = window.DeviceOrientationEvent as
  | (typeof DeviceOrientationEvent & {
      requestPermission?: () => Promise<string>;
    })
  | undefined;

const needsPermission =
  typeof OrientationEvent?.requestPermission === 'function';

if (coarsePointer && OrientationEvent && !needsPermission) {
  motionActive = true;
  window.addEventListener('deviceorientation', handleOrientation, true);
}
```

要点：

- 这段必须留在 `if (hero && canvas && !reduceMotion)` 内部，减少动效模式下完全不启用；
- `needsPermission` 只在 iOS 13+ 为 `true`，此时什么都不做、不弹窗；
- 未来如果更多浏览器引入权限 API，这里会退化为「不启用」，而不是擅自弹窗，属于安全默认；
- 页面生命周期内不需要移除监听，保持现状即可。

### 5.2 字体策略（推荐方案）


实施步骤：

```bash
  --text-file=scripts/font-chars.txt \
```
